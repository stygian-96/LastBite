# LastBite Backend Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the API, jobs and database for a surplus-food pickup marketplace, ready for the website to call.

**Architecture:** The backend is a standalone Hono API in `backend/`, and the website will live separately in `frontend/`. It exposes REST routes under `/api/v1`. Route handlers stay thin and call domain modules in `src/modules`, which use PostgreSQL transactions for stock and money. Razorpay, messaging and file storage sit behind interfaces, so all tests run against fakes and a real Postgres.

**Tech Stack:** TypeScript, Hono on Node, PostgreSQL 16, Drizzle ORM with the `pg` driver, Zod, Vitest, Docker Compose.

**Spec:** `docs/backend-implementation.md`. Read it first. Its section 5 SQL, section 8 routes and section 10 edge cases are requirements.

## Global Constraints

- Money is integer paise. Commission is `Math.round(price * bps / 10000)`, per order.
- Timestamps are UTC `timestamptz`, shown in IST. India has no DST, so use a fixed +05:30 offset.
- `service_date` is the IST calendar date of a drop's pickup start.
- Hold is 5 minutes from Reserve. The expiry job adds 60 seconds of grace.
- Sales end 15 minutes before pickup end. No-show is marked 30 minutes after pickup end.
- Selling is one bag per order, per outlet, per night.
- Razorpay is confirmed by webhook only. A browser callback never marks an order paid.
- Time-sensitive functions take `now: Date`, and SQL uses that parameter rather than `now()`, so tests control the clock.
- Provider calls never happen inside a database transaction. Transactions write rows, then jobs call providers.
- Errors use `{ "error": { "code": string, "message": string } }`.
- Every route lives under `/api/v1`.
- Maps, coordinates, distance and waitlists are out of scope.
- Do not add a dependency that this plan doesn't name without asking.
- Each commit message ends with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. A capture webhook racing the expiry job on the same order must leave one final state and a correct `reserved_count`. Tested in Task 12.
2. A drop cancelled while a customer is still paying must end in a refund, never a bag that doesn't exist. Tested in Task 13.
3. Pickup at 00:20 IST for a window that started the night before must find the order, because the calendar date has changed. Tested in Task 14.
4. Staff passing another brand's or outlet's ID must get 403, including franchisees reading each other's earnings and staff who were removed. Tested in Tasks 5 and 17.
5. The same phone signing in on two devices, each holding a bag at one outlet, must keep one order and show it, not return a 500. Tested in Task 11.
